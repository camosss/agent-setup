
















- 답변에 원문자 숫자(①②③ 등)를 쓰지 않는다. 번호가 필요하면 1. 2. 3. 처럼 일반 숫자를 쓴다.
- 사용자에게 보이는 모든 답변은 한국어로 쓴다. 짧은 답, 중간 보고, 표, 요약도 예외 없다. 영어로 쓴 초안이 있으면 보내기 전에 한국어로 바꾼다. 코드, 명령어, 파일 경로, 식별자는 원문 그대로 둔다.
- 작업과 커밋을 마치면 "지시를 기다립니다" 같은 평서문으로 끝내지 않고, 마지막 줄에 "push 후 draft PR, AI 리뷰 확인·반영까지 진행할까요?" 라고 묻는다. 사용자가 "응/ㅇㅇ/진행" 이라고 답하면 다음을 중간 확인 없이 진행한다: 1. feature 브랜치 push 2. draft PR 생성 3. AI 리뷰가 달리면 확인 4. 반영할 코멘트는 수정 커밋 후 push, 반박·보류는 정리해 보고 5. 반영한 리뷰 스레드는 resolve (반박·보류 스레드는 남긴다). 머지, main/release/hotfix/deploy 브랜치 push, 브랜치 삭제는 이 승인에 포함되지 않으며 따로 묻는다.
- 사용자가 Herdr의 기능 조사, 터미널·창 조작, 다른 창 에이전트와의 협업, 원격 연결, 설정이나 자동화를 요청한 경우에만 `~/.claude/agent-guides/herdr.md`를 읽고 따른다. 필요한 상세 문서(`herdr/operations.md`, `herdr/automation.md`)만 이어서 읽는다. 일반 터미널 실행이나 병렬 작업이 유용하다는 이유만으로 Herdr를 사용하지 않는다. 예외: 아래 조사 규칙과 작업 세션 규칙에 따라 세션을 여는 일은 요청 없이 한다.
- 대화를 압축(compact)할 때 요약에 반드시 남긴다: 작업 목표, 작업 카드 번호, 브랜치와 PR 번호, 진행 상태와 남은 일(남은 QA 항목 포함), 확정된 결정과 그 규칙, 이 세션의 이름과 역할(조율 세션이면 담당 스레드와 세션 이름). 도구 출력 원문과 시행착오는 버린다.
- 여러 파일이나 레포를 훑는 조사, 넓은 검색은 서브에이전트가 아니라 현재 탭 오른쪽에 Herdr 작업 세션을 열어(`herdr pane split <현재 pane> --direction right` + `herdr agent start <이름>`) 사용자에게 보이게 진행하고 결론만 받는다. 위치를 아는 파일 하나를 읽는 일은 직접 한다.
- 조율 세션은 작업 세션을 작업 단위로 연다. 작업 세션의 완료 보고(PR, 리뷰 반영 완료 등)를 검증하면 묻지 않고 그 세션을 닫고, 다음 작업 때 새로 열어 지시한다. 방법은 dispatch-work-sessions 스킬을 따른다.
- 개인 설정(`~/agent-setup/paths.txt` 에 있는 파일: `~/.claude/settings.json`, 이 파일, `~/.claude/hooks`, 개인 스킬, Hammerspoon, Herdr, Ghostty 설정)을 바꾸면 작업 끝에 `~/agent-setup/sync.sh` 를 실행해 레포 camosss/agent-setup 에 반영한다(공개 레포라 비공개 정보는 sync.sh 가 거른다). 새로 관리할 설정 파일이 생기면 `paths.txt` 에 한 줄 추가한다.
- `[context-hygiene]` 알림이 붙으면 그 지시대로 처리하고 답변 끝에 한 줄만 붙인다. 인수인계 메모는 쓸지 묻지 않고 바로 쓴다. 메모를 받아 이어받은 새 세션은 내용을 확인한 뒤 메모 파일(`~/.claude/handoffs/`)을 지운다. 같은 권유를 반복하거나 작업 도중에 끊지 않는다.
